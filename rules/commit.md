---
name: commit
title: Commit your changes
applies: all
---

Commit your own changes to the bots repo often, as each piece of work there is
done: what you changed, in whatever folder it is, and what the kit wrote in
your own bot's folder (its files there and your book of sessions). Stage each
file by name and name them in the commit too (`git commit -- <files>`), so
nothing another session staged goes in with yours. What no bot owns (init's
files, the defaults, the user's rules and skill lists) is Bot Father's to
commit. Commit yours even when the repo has no commit yet or holds files that
are not yours; leave those to their owner.

Committing is not pushing: pushing is the user's call. A clone in your work dir
follows its own repo's rules. When a commit fails, for example on another
session's index lock, try again, and say so if it still fails.
